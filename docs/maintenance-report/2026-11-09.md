## Security Updates

| Dependency | Current | Latest | Severity | CVE | Action |
| --- | --- | --- | --- | --- | --- |
| Pace.js (`Content/Hola/js/pace.min.js`) | 1.2.4 | 1.3.1 (2026-11-05) | Medium advisory (CVSS 4.4, `AV:N/AC:H/PR:L/UI:R/S:C/C:L/I:L/A:N`; CWE-79, CWE-1321). **Not exploitable on this site**, see below | None assigned. GHSA-5fmc-v4p3-pqpg, vulnerable range `< 1.3.0`, patched 1.3.0 | Updated to 1.3.1 (`c29aef6`) |

**The advisory.** Pace read its options from the first element carrying a `data-pace-options` attribute, not only its own `<script>` tag. On a page that shows user-supplied HTML and runs Pace after that content, an attacker could pollute `Object.prototype` through a `__proto__` key, or inject HTML through the `className` option (inserted unescaped into the progress bar). Published 2026-11-02 01:14 UTC.

**Why it was not exploitable here.** `index.html` and `404.html` contain no `data-pace-options` attribute, there is no user-supplied HTML and no `innerHTML`/`insertAdjacentHTML`/`document.write`/`location.hash`/`location.search` sink, and Pace loads as a plain `<script>` in `<head>` (`index.html:40`), which the advisory itself lists as an unaffected placement. The update is hygiene, not an emergency fix.

**Verified, not inferred.** A scratch harness loaded Pace *after* user markup carrying a hostile `data-pace-options` (the vulnerable placement) in headless Chromium:

| Pace build | `Object.prototype` polluted | HTML injected through `className` |
| --- | --- | --- |
| 1.2.4 (the build that was vendored) | **yes** | **yes** |
| 1.3.1 | no | no |

So the advisory applies to 1.2.4 as shipped, and 1.3.1 closes it.

**Why this was found late, and a method change.** The GitHub global advisory database has **no record** of this advisory (`GET /advisories/GHSA-5fmc-v4p3-pqpg` → 404; `affects=pace-js` → 0), so the range check used in every earlier run could not see it. It is visible only in the upstream repository's own `security-advisories` list and in its release notes. Earlier reports' "Pace.js 1.2.4 = latest, 0 advisories" was correct when written: 1.3.0 was published about 7 hours after the 2026-11-02 run. From this run on, the dependency audit also queries each upstream repository's `security-advisories` and recent releases, not only the global database. Done this run for the other vendored libraries, see the table below: nothing new.
