## Security Review

### Issues found and fixed

1. **Outdated, CDN-loaded Bootstrap 3.3.7 in `404.html` (Medium — supply chain / outdated dependency)**
   `404.html` loaded `bootstrap.min.css` from `cdnjs.cloudflare.com` pinned to version 3.3.7
   (EOL since 2019), with no Subresource Integrity (SRI) hash — so the page's styling was
   fully trusting cdnjs to keep serving that exact, unmodified file indefinitely, with no
   tamper detection if it didn't.
   **Fix:** `404.html` now loads the already-vendored, self-hosted `Content/bootstrap.min.css`
   (4.6.0) instead, removing the external CDN dependency entirely. The Bootstrap 3 → 4 grid
   class rename (`col-sm-offset-1` → `offset-sm-1`) was applied so the layout is unchanged.
   Verified with a headless-browser screenshot before and after — page renders identically.

2. **Unused, dead Bootstrap 4.6.0 CSS bundle (Low — repo hygiene / attack surface)**
   `Content/bootstrap.css`, `bootstrap-grid.*`, and `bootstrap-reboot.*` (plus their
   `.map` sourcemaps — ~900 KB total) were vendored but never referenced by any page.
   **Fix:** Removed the unused variants; `bootstrap.min.css` (+ its sourcemap) was kept and
   is now actually used by `404.html` (see above).

3. **CVE-2024-6531 (Bootstrap carousel XSS, disputed) — investigated, not applicable.**
   This CVE covers Bootstrap 4.0.0–4.6.2's carousel *JavaScript* plugin. The Bootstrap
   maintainers rescinded/disputed it as out-of-scope for their security model. It is moot
   here regardless: this repository never vendors or loads `bootstrap.js` — only the CSS
   is used, and the CSS is not affected.

4. **Stray local debug log committed to the repository (Low — hygiene)**
   `debug.log` (a Chromium/Edge internal settings error log, unrelated to the project) was
   committed in the initial commit. **Fix:** removed.

## CI/CD

This repository had no CI/CD prior to this maintenance pass. **Added**
`.github/workflows/pages-ci.yml`:
- `lint-html`: runs `htmlhint` against `*.html` using the new `.htmlhintrc` config on every
  push/PR to `main`.
- `check-links`: runs `lychee` (offline mode — checks local relative links/asset paths only,
  does not depend on flaky external-network availability in CI) on every push/PR to `main`.

Both jobs must pass before a pull request can be merged (once branch protection is enabled
on `main` — repository-level branch protection was not modified by this pass, since that is
a GitHub repository setting outside this codebase).

Deployment is unaffected: GitHub Pages continues to serve `main` directly with no build
artifact step.
